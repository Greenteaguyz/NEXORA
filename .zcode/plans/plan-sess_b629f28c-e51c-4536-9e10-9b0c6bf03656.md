# Paid-Game Removal Reverts the Payment (library remove → legitimate not-owned)

## Behavior contract
- **Free games**: remove from library = today's behavior, unchanged (nothing to revert).
- **Paid games**: removing from the library now performs a real payment revert BEFORE the entitlement drops:
  1. Find the user's `confirmed` order for that game (price > 0).
  2. **Wallet-tender orders** (paymentMethod starts with `NEXORA Store Wallet`) → refund via the Phase 1 finance ledger: new `refundWallet` on `PAYMENTS_DATA` writes a completed `refund_credit` ledger entry with correct `balanceAfter` and syncs the legacy wallet (mirror of `topUpWallet`).
  3. **Card / ABA PayWay / KHQR orders** → no mock money movement (can't refund external rails); the order cancel is the record.
  4. Order status → new additive `'refunded'` value on `OrderStatus`.
  5. Library entry removed (existing behavior) → `isOwned` flips false and the price/Buy state shows again — now legitimate, because the payment was actually reverted.
- Both removal paths get it: **library page** `confirmRemove` and **game-detail** `confirmRemoveFromLibrary`. Toast states the outcome ("$X refunded to wallet" / "purchase reverted").

## Changes
- `order.model.ts`: add `'refunded'` to `OrderStatus` (additive).
- `tokens.ts` + `mock-orders-data.service.ts`: `revertOrder(orderId): Observable<Order>` (confirmed → refunded, persist; no-op if already terminal).
- `tokens.ts` + `mock-payments-data.service.ts`: `refundWallet(userId, amountMinor, reference)` — ledger `refund_credit` entry + legacy sync (reuses existing ledger helpers).
- `library.component.ts` + `game-detail.component.ts`: orchestration in the two remove flows (find order → refund if wallet → revert → remove entry → toast).
- No changes to `isOwned` semantics, purchase flow, or the PayWay sheet.
