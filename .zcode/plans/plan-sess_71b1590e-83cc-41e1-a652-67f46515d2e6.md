# NEXORA Account Payment & Wallet Page — Final Implementation Plan

**Goal:** Authenticated users manage payment methods (Card, KHQR-with-bank), view/top-up a NEXORA wallet, and redeem gift cards at `/account/payment`, persisted per-user in localStorage. Checkout stays untouched.

## Corrected architecture (per review)

- **Service pattern**: `PaymentsDataService` interface in `src/app/core/data/tokens.ts` (Observable-based, matching `OrdersDataService`): `getMethods(userId)`, `addMethod(userId, dto)`, `removeMethod(userId, methodId)`, `setDefaultMethod(userId, methodId)`, `getWallet(userId)` (balance + transactions), `topUp(userId, amount, methodId)`, `redeemGiftCard(userId, code)`.
- **Mock impl**: `src/app/core/data/payments/mock-payments-data.service.ts` — `initData()`/`persist()` via `LocalStoreService` (SSR-safe by inheritance), seed-on-empty, exact `mock-orders-data.service.ts` shape.
- **Pure logic core** (testable without DI): `src/app/core/data/payments/payment-logic.ts` — `luhnCheck()`, `isCardExpired()`, `isDuplicateCard()`, `applyRemoveAndReassignDefault()`, `redeemGiftCard()`, `formatUsd`/`approxKhr` (rate constant 4100). Service is a thin delegate.
- **Storage keys** (via LocalStoreService prefix): `payment_methods`, `wallet_balances`, `wallet_transactions`, `gift_cards`.

## New files

1. `src/app/core/models/payment.model.ts` — `PaymentMethod` (discriminated union: `card` {brand, holder, last4, expiry}, `khqr` {bank, handle, isDefault}), `WalletTransaction`, `GiftCard`, DTOs.

5. `src/app/shared/ui/payment-brand-mark/payment-brand-mark.component.ts` — inline SVG marks (visa/mastercard/aba/khqr), `viewBox`, aria-hidden, `input()` signal.

7. `src/app/features/account-payment/account-payment.component.ts/.html/.css` — page: wallet card (balance, KHR approx line, Top-up modal, History), methods list (add/remove/default modals per bespoke-modal pattern, Escape+focus parity), gift-card redeem card, recent activity.

## Acceptance criteria (revised set)

- AC-001 page renders per-user methods with SVG marks, masked numbers, DEFAULT badge, empty state.
- AC-002 add card: valid persists + toast + reload-survives; Luhn/expired/duplicate rejected with inline error, zero mutation.
- AC-003 [revised] add KHQR: bank select (ABA default, ACLEDA/Wing listed), simulated link (~1.5s) → persists with bank stored; KHQR card component renders mock QR.
- AC-004 remove default → auto-reassign, exactly one default per user at all times; Cancel = no-op.
- AC-005 guard redirect + profile link resolves; crawler updated.
- AC-006 lazy seeding for returning visitors: new keys seeded on init, zero console errors, other keys untouched.
- AC-007 wallet top-up via saved method credits balance + writes transaction; gift redeem credits balance; activity list shows both.
- AC-008 design compliance: tokens only (brand tokens documented), grounded hover, 6px buttons/8px cards/16px modals, AAA contrast; `npm run verify` fully green with new counts reported.

## Risks & mitigations (carried from review)

- Seed invariants pinned by tests → payments seed is additive-only; `test:unit` right after seed change.
- NG0203 in direct service tests → all logic in pure functions; service untested directly (consistent with repo).
- Reset-database wipes new keys → `initData()` re-seeds on next service construction (same as orders).
- KHQR realism → fake QR encodes nothing; no real names/account numbers in repo.

## Out of scope (next PR)

Checkout rewire to consume saved methods + wallet as tender (unblocks the UX expectation gap), purchase-modal "Manage" link, currency switcher, i18n, promotions, pre-order.

## Execution order

Models → pure logic + unit tests → seed → service + tokens/config wiring → route → shared UI components → page → profile link → integration/audit tests → `npm run verify` (fix until green) → report with pass/fail + test counts.
