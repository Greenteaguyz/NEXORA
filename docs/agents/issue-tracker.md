# Issue Tracker Configuration

## Default Tracker
- **Type**: `markdown` (Local task files under `docs/tickets/` or GitHub issues via `gh` CLI if configured)
- **Local Ticket Directory**: `docs/tickets/`
- **GitHub Integration**: If GitHub CLI (`gh`) is authenticated, `/to-tickets` can optionally create issues directly on the remote repository.

## Ticket Format
Each ticket generated by `/to-tickets` adheres to the following structure:
```markdown
# [TYPE-NNN] Title of the Ticket

**Status**: Ready | In Progress | Done
**Assignee**: AI Agent / Developer
**Type**: Feature | Bug | Spike | Refactor | Polish
**Priority**: High | Medium | Low

### Goal
Clear statement of what user or system outcome will be achieved.

### Tracer Bullet / Scope
- [ ] Minimal end-to-end slice implemented
- [ ] Unit / Integration test added
- [ ] Verification passing (`npm run verify`)

### Acceptance Criteria
- [ ] AC-1: Specific verifiable behavior
- [ ] AC-2: Specific error handling behavior
```
